## 统一术语：四层架构

在进入任何范式之前，先对齐四个容易混用的层次。本系列所有文档统一使用这组术语，避免概念漂移。

| 层次 | 核心职责 | 典型样本 |
|---|---|---|
| **Agent** | 目标、模型、工具与决策策略构成的执行单元 | 各 SDK 中的 `Agent` 抽象 |
| **Agent Harness** | 把模型包进可工作的循环：上下文、工具、环境、权限、停止、恢复和交互 | mini-SWE-agent、Pi、Deep Agents |
| **Agent Runtime / Control Plane** | 状态、事件、checkpoint、并发、调度、持久化和恢复 | OpenHands SDK、LangGraph、DeerFlow |
| **Agent Product** | 在 Harness/Runtime 上增加 CLI、IDE、TUI、桌面端、账号与渠道体验 | Codex、OpenCode、Cline、OpenClaw |

一个成熟系统通常是这些层的组合，而不是四选一：

```text
Agent Product (CLI / IDE / UI / 渠道)
  └─ Agent Harness
       ├─ control loop / policy
       ├─ context / memory
       ├─ tools / workspace / permissions
       └─ delegation / interaction
            └─ Agent Runtime
                 ├─ state / events / checkpoints
                 ├─ scheduling / concurrency / resume
                 └─ tracing / evaluation / operations
```

因此，LangGraph 和 Codex 不应直接比较"谁更强"：前者主要是状态化执行底座，后者是包含 Harness 的完整 Coding Agent 产品。

### 配套术语速查

| 术语 | 含义 |
|---|---|
| **History** | 原始消息轨迹，按时间排列的完整记录 |
| **Context** | 本轮模型实际输入，是从 history/memory/system 中编译出的 working set |
| **Checkpoint** | 可恢复的执行状态快照，用于中断后继续 |
| **Memory** | 跨步骤或跨会话保留的信息，含事实、经验、技能 |
| **Delegation（委派）** | 父 Agent 发起后等待，子 Agent 自主跑多轮 loop，有独立上下文 |
| **Handoff（移交）** | 父 Agent 退场，子 Agent 接管原会话与用户 |
| **Agent-as-tool** | 父 Agent 每轮主动调用，子 Agent 只返回一次结果 |
| **Fan-out / fan-in** | 并行委派 + 汇总，是 delegation 的并发形态 |
| **Heartbeat** | 定期 tick，驱动主动循环、租约续期和存活检测 |
| **Cron / Scheduler** | 精确时间点触发任务，管理注册、去重和恢复 |
| **Event subscription** | 订阅外部事件并触发处理，与心跳/定时正交 |

**三组强依赖：**

1. **Action Model → Workspace 隔离 → 权限与 Sandbox**：行动格式决定了权限能在什么粒度上拦截；执行环境决定了 sandbox 的强制方式。
2. **上下文装配 → Durable State → 长期记忆/子 Agent**：压缩产生的 artifact 需要持久化才能跨会话；记忆和委派都建立在上下文可控的基础上。
3. **Durable State + 子 Agent → Gateway/Scheduler**：常驻运行的 Agent 必须能处理中断和恢复；定时任务和多渠道接入天然涉及委派。

其余范式之间是弱依赖或互补关系，可以跳读。

## 四条学习路线

### 路线一：默认路线（完整序列）

适合想系统建立 Harness 心智模型的工程师。

```
01 极简 Loop → 02 Action Model → 03 Workspace隔离 → 04 权限Sandbox
  → 05 上下文装配 → 06 Durable State → 07 长期记忆 → 08 子Agent委派
  → 09 Gateway/Scheduler → 10 可观测性 → 11 领域接口
```

预计阅读时间：约 4–6 小时（每篇 20–30 分钟）。

### 路线二：快速路线（5 篇精华）

适合已经有 Agent 开发经验、想快速抓住核心范式的架构师。

```
01 极简 Loop → 04 权限与 Sandbox → 05 上下文装配
  → 06 Durable State → 08 子 Agent 委派
```

这五篇覆盖了一个 Agent 系统从"能跑"到"可控"的五个关键工程问题：循环怎么转、能力怎么限、上下文怎么管、挂了怎么恢复、大任务怎么拆。

预计阅读时间：约 2 小时。

### 路线三：Coding Agent 路线（6 篇）

适合专注于代码生成、代码编辑、CLI/IDE Agent 的团队。

```
01 极简 Loop → 02 Action Model → 03 Workspace隔离
  → 04 权限与 Sandbox → 06 Durable State → 10 可观测性与评测
```

重点关注：代码编辑的动作空间、文件系统隔离、审批流、会话恢复、trajectory 评测。第 11 篇领域接口可作为补充（代码编辑本身就是一种领域接口）。

预计阅读时间：约 2.5 小时。

### 路线四：长期 Agent 路线（6 篇）

适合做 24/7 常驻 Agent、个人助理、运维机器人、跨渠道 Bot 的团队。

```
01 极简 Loop → 05 上下文装配 → 06 Durable State
  → 07 长期记忆 → 08 子 Agent 委派 → 09 Gateway/Scheduler
```

重点关注：长任务上下文管理、持久化与恢复、跨会话记忆、子任务委派、多渠道接入与定时任务。第 10 篇可观测性是生产运营的必备补充。

预计阅读时间：约 2.5 小时。

## 如何使用单篇文档

每篇文档采用相同的十章结构，建议按以下方式使用：

### 快速浏览（3 分钟）
只读 **§1 一句话掌握** 和 **§10 边界与延伸阅读**，判断这篇是否是你现在需要的。

### 建立直觉（10 分钟）
读 **§2 为什么需要它**（理解问题从何而来）+ **§3 最小概念模型**（伪代码 + 数据流图）。读完后你应该能用一句话解释这个范式解决什么核心问题。

### 深入工程实现（15 分钟）
读 **§4 关键设计决策**（3–5 个真正影响系统性质的取舍）+ **§5 代表项目代码解读**（主项目的原生语言代码，证明核心设计）。

重点关注代码中标注的 2–4 个关键点——这些是该范式的工程精髓。代码片段中的错误处理、终止条件和状态变化不要跳过。

### 横向对比（5 分钟）
读 **§6 热门项目横向对比**，了解不同项目在同一问题上的不同取舍，以及哪些设计是行业共识、哪些仍有分歧。

### 提炼方法论（5 分钟）
读 **§7 方法论抽象**，把项目实现上升为可迁移的设计原则、决策顺序和不变量。这是从"会用某个项目"到"能设计自己的系统"的关键一步。

### 动手实践（30–60 分钟）
做 **§8 实践练习** 中的练习。亲手实现一个最小版本，比读十遍代码更能建立工程直觉。

### 自查与落地（5 分钟）
用 **§9 掌握检查** 中的自测问题检验理解；用生产检查清单对照你当前的系统。常见误区部分尤其值得注意——很多是真实项目踩过的坑。

## 阅读建议

1. **不要按项目读，要按范式读**。同一个问题在五个项目里有五种解法，横向对比比纵向通读单个项目更有效。
2. **先有最小闭环，再加复杂度**。如果你还在做第一个 Agent，先把第 01 篇的练习做了，再决定要不要引入 Workspace 抽象或子 Agent。
3. **源码事实、教学简化、方法论推断要区分**。每篇文档明确标注了哪些是源码事实、哪些是教学等价代码、哪些是作者的方法论推断。引用到生产决策前，建议用官方仓库核验。
4. **本系列不是功能清单**。每篇只聚焦一个范式的核心设计决策和工程取舍，不追求覆盖项目的全部功能。完整功能请参考各项目官方文档。
